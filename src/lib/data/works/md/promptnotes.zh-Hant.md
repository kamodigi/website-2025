## 開發背景

在 Claude Code 和 Codex 中，如果在輸入提示詞的過程中按下 Enter，內容就會立刻傳送給 AI。我有過很多次把寫到一半的提示詞誤發出去的經歷。

promptnotes 是一個專門用來編寫傳送給 AI 之前的提示詞的編輯器。Enter 可以放心地用來換行。這個應用程式的用途不是傳送，而是「先寫好存起來，之後複製使用」，所以它沒有呼叫 AI 的功能。

所有筆記都以本地的 `.md` 檔案儲存。可以與其他工具共存，資料也可以自由帶走。

## 技術選型

- **Tauri v2**：桌面應用程式的基礎。面向 macOS 和 Linux 發布。
- **SvelteKit**：介面用 SvelteKit（static adapter）製作。和這個網站一樣，是我喜歡的框架。
- **Rust**：儲存檔案、檢查更新等接近作業系統的處理，作為 Tauri 的命令用 Rust 編寫。
- **CodeMirror 6**：Markdown 的語法高亮，以及列表和括號的補全都交給它。

## 使用 ori 的開發方式

開發時使用了我自己做的框架 [ori](/works/ori)。首先在 `idea.md` 中寫下想做的東西和「不能做的事」。然後用 ori 生成 DDD 的文件（`.ori/domain/`），此後都以這份文件作為唯一的事實來源。

在文件中，我把應用程式劃分為 4 個限界上下文（建立筆記、資訊流、設定、更新）。實作以 slice 為單位（建立筆記、自動儲存、更新搜尋條件等），先寫測試再推進。想修改規格時，不改程式碼，而是修改領域文件，並重新完成受影響的 slice。

## 設計上堅持的原則

在 `idea.md` 中，我一開始就寫下了要遵守的事項。特別是把過去的實作中 AI 犯過的錯誤，作為禁止再犯的事項列了出來。

- **只用單欄版面配置**：不加側邊欄。AI 一聽到「筆記應用程式」，就想做成側邊欄加主欄的結構。
- **不放應用程式名稱的標題列**：已經有作業系統的標題列，不在它下面再做一條同名的橫條。
- **預覽和編輯使用同一套渲染機制**：如果在用於顯示的 HTML 和用於編輯的 CodeMirror 之間切換，行高會變化，座標就會錯位。因此始終顯示 CodeMirror，只透過切換 `readOnly` 進入編輯。

區塊的狀態只有 IDLE（無操作）、FOCUSED（用鍵盤選中）、EDITING（編輯中）3 種。因為把狀態遷移寫進了文件，多餘的狀態就不容易增加。

## 遇到的困難

- **更新通知**：檢查更新的功能（slice）已經做好了，但在 v0.2.2 和 v0.2.3 中，忘了把它接到應用程式啟動時的處理上。即使發布了新版本也不會通知，只能請使用者手動替換。在 v0.2.4 中，接上了啟動時和每 24 小時的檢查。
- **macOS 的分發**：因為沒有加入 Apple Developer Program，應用程式沒有經過公證。首次啟動時會出現 Gatekeeper 的警告，所以我在 README 中寫了繞過的步驟。
- **固定工具鏈**：用 Nix 的 flake 固定了開發環境，但每次更新依賴都需要修正雜湊值。
