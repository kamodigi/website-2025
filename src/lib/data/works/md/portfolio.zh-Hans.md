## 关于本网站

这是米谷拓哉的作品集网站（也就是本网站）。使用 SvelteKit 和 TypeScript 构建，介绍个人开发的作品和技术栈。这次在开发中引入了 AI，尝试用 Gemini CLI 和 Kiro 进行 AI 驱动开发。

## 技术选型

### 选择 SvelteKit 的理由

采用 SvelteKit，很大程度上是因为这是我个人喜欢的框架。原因在于，Svelte 的设计就像是 HTML 和 CSS 的扩展。我也喜欢 React，它全部用 JS 完成，这是它的优点；但 Svelte 的写法感觉像是 HTML 的自然延伸，写起来很舒服。

另外，Svelte 编译后会变成没有额外开销的 HTML、CSS 和 JavaScript，这也是我选择它的理由。React 和 Vue 需要运行时，我认为对小型 Web 应用来说过于繁重。此外，Svelte 使用 JavaScript 库时不需要包装层，这一点也很有吸引力。

### 没有采用 TailwindCSS 的理由

这次没有采用 TailwindCSS。我本来就对 Tailwind 持怀疑态度。把样式写在类名里，偏离了语义分离的原则。另外，如果要用预设之外的值，就需要写 JIT（Just-In-Time）的语法；既然如此，我觉得直接写 CSS 就好了。

而且近年来可以借助生成式 AI，不使用特殊语法也能轻松写出原生 CSS。我感觉这一变化大大降低了传统 CSS 编写的门槛。

## AI 驱动开发的实践

在这个项目中，我尝试了使用 Gemini CLI 和 Kiro 的 AI 驱动开发。不过实际上，更多的工作流程是先让 AI 写代码，再由我自己手动修改大约三成。

特别头疼的是，Gemini 经常不按本项目使用的 Svelte 5，而是按 Svelte 4 的语法来写。另外，AI 似乎几乎不了解 Paraglide JS，所以多语言相关的部分全部由我自己编写。

我深切体会到，AI 驱动开发并不是完全自动化的；只有由人对 AI 生成的代码进行恰当的审查和修改，它才会成为真正可用的代码。尤其是对于新版本的库或小众的库，AI 的知识往往跟不上，因此人的判断不可或缺。

## 实现细节

### 使用 Three.js/Threlte 实现交互式主视觉

在这个作品集中，我特别在首页的主视觉上下了功夫。利用 Three.js（准确地说是 Svelte 实现的 Threlte），制作了动态的几何图案。此外，还实现了响应用户点击的交互效果。

这是我第一次接触 Three.js，正好是从基础开始学习 3D 图形的好机会。WebGL 的原理、着色器的概念、3D 空间中的坐标系等，我学到了很多新知识。今后也想积极地在 Web 上运用 3D 表现。

### 用 Markdown 管理内容

作品信息用 Markdown 文件管理。在前置元数据（Front Matter）中写元信息，正文则可以作为技术文章来阅读。

用 Markdown 管理与 Git 的配合非常好，版本管理也很容易。变更历史便于追踪，差异也能清楚地确认。比起使用 CMS 更简单，我觉得对工程师来说是很好用的机制。

元信息同时准备了日语和英语两种版本，并与 Paraglide JS 配合，实现了多语言支持。

## 部署与基础设施

### Coolify 与日本国内基础设施的选择

部署选择 Coolify，是因为我最近自己租了服务器并在上面运行 Coolify。Vercel 也是很有吸引力的部署平台，但我特意选择 Coolify，是因为可以使用日本国内的基础设施。

日本的数字贸易逆差在不断扩大，作为 IT 从业者，这是我关心的社会问题。我自己能做的，只是借助开源软件尝试使用日本国内的基础设施；但如果这种做法能推广开来，我认为可以成为应对日本数字贸易逆差的一种对策。这虽然只是个人的一个小选择，但我把它看作履行技术人员社会责任的一种方式。

## 开发中遇到的困难

开发中遇到的困难主要在设计和 UI/UX 方面。我没有学过设计，所以一边寻找可以参考的网站设计，一边摸索着推进。当然，生成式 AI 也帮了很大的忙。

比起技术实现，我更深刻地体会到，做出既好用又美观的界面有多难。设计中有很多感性的部分，也没有唯一的正确答案，所以一直在不断试错。
