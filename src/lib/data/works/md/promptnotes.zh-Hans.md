## 开发背景

在 Claude Code 和 Codex 中，如果在输入提示词的过程中按下 Enter，内容就会立刻发送给 AI。我有过很多次把写到一半的提示词误发出去的经历。

promptnotes 是一个专门用来编写发送给 AI 之前的提示词的编辑器。Enter 可以放心地用来换行。这个应用的用途不是发送，而是“先写好存起来，之后复制使用”，所以它没有调用 AI 的功能。

所有笔记都以本地的 `.md` 文件保存。可以与其他工具共存，数据也可以自由带走。

## 技术选型

- **Tauri v2**：桌面应用的基础。面向 macOS 和 Linux 发布。
- **SvelteKit**：界面用 SvelteKit（static adapter）制作。和这个网站一样，是我喜欢的框架。
- **Rust**：保存文件、检查更新等接近操作系统的处理，作为 Tauri 的命令用 Rust 编写。
- **CodeMirror 6**：Markdown 的语法高亮，以及列表和括号的补全都交给它。

## 使用 ori 的开发方式

开发时使用了我自己做的框架 [ori](/zh-hans/works/ori)。首先在 `idea.md` 中写下想做的东西和“不能做的事”。然后用 ori 生成 DDD 的文档（`.ori/domain/`），此后都以这份文档作为唯一的事实来源。

在文档中，我把应用划分为 4 个限界上下文（创建笔记、信息流、设置、更新）。实现以 slice 为单位（创建笔记、自动保存、更新搜索条件等），先写测试再推进。想修改规格时，不改代码，而是修改领域文档，并重新完成受影响的 slice。

## 设计上坚持的原则

在 `idea.md` 中，我一开始就写下了要遵守的事项。特别是把过去的实现中 AI 犯过的错误，作为禁止再犯的事项列了出来。

- **只用单栏布局**：不加侧边栏。AI 一听到“笔记应用”，就想做成侧边栏加主栏的结构。
- **不放应用名的标题栏**：已经有操作系统的标题栏，不在它下面再做一条同名的横条。
- **预览和编辑使用同一套渲染机制**：如果在用于显示的 HTML 和用于编辑的 CodeMirror 之间切换，行高会变化，坐标就会错位。因此始终显示 CodeMirror，只通过切换 `readOnly` 进入编辑。

块的状态只有 IDLE（无操作）、FOCUSED（用键盘选中）、EDITING（编辑中）3 种。因为把状态迁移写进了文档，多余的状态就不容易增加。

## 遇到的困难

- **更新通知**：检查更新的功能（slice）已经做好了，但在 v0.2.2 和 v0.2.3 中，忘了把它接到应用启动时的处理上。即使发布了新版本也不会通知，只能请用户手动替换。在 v0.2.4 中，接上了启动时和每 24 小时的检查。
- **macOS 的分发**：因为没有加入 Apple Developer Program，应用没有经过公证。首次启动时会出现 Gatekeeper 的警告，所以我在 README 中写了绕过的步骤。
- **固定工具链**：用 Nix 的 flake 固定了开发环境，但每次更新依赖都需要修正哈希值。
